# uNdoqo V2.5 — Persistent commerce implementation

## Implemented in source

- Frozen server-calculated prices and currency quotes; pending order and line items are saved to Supabase before PayPal checkout.
- PayPal capture is verified against the saved order; stable idempotency key reduces double-capture risk.
- Signed PayPal `PAYMENT.CAPTURE.COMPLETED` webhook, with API postback signature verification and independent PayPal order retrieval.
- Atomic database finalisation records payment, allocates sequential invoice reference, sets `paid` status, creates consultation bookings or pending digital entitlements.
- Order lookup uses a private receipt token, and a browser order-status page reads the latest order from session storage.
- Read-only admin order dashboard with server-side administrator access-key verification; this is **not** a complete employee identity-management system.
- Original contact page, complete navbar across pages, original logos, invoice signature, catalogue and media preserved.

## Not yet production-ready / not performed

- No Supabase project or credentials are provided. SQL migration has not been executed against a live project.
- No PayPal webhook has been registered; sandbox webhook integration not tested end-to-end.
- No licensed digital PDF source files or protected download delivery have been configured; entitlements intentionally remain `pending_asset`.
- No automated email issuing, financial ledger / tax setup, refund handling or merchant FX feed is active.
- No production hosted release or live transaction has been performed.
